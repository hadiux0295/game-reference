## 1. 한 줄 정의
조준과 위치 선정으로 상대를 먼저 쓰러뜨리는 게임. 설계 변수는 셋이다: **TTK**(얼마나 빨리 죽나), **판정 방식**(hitscan/투사체), **넷코드**(누가 판정하고 랙을 어떻게 보상하나). 이 셋이 맵·무기·BM을 결정한다.

## 3. 핵심 루프·시스템

- **TTK(Time-to-Kill) 설계**: TTK가 짧을수록 "먼저 본 쪽"이 이기고(포지셔닝 게임), 길수록 에임·스킬·힐이 개입한다. VALORANT Vandal은 헤드 160/몸 40/다리 34 (거리 감쇠 없음) — 헤드 원샷 설계 (3rd-party 위키 수치, Riot 공식 수치표 미확인) [19]. Call of Duty BO6은 Treyarch가 CoD Next에서 "Cold War보다 약간 빠른" 정도로 설명, AR 평균 약 320ms (2차 보도) [20]. Overwatch는 5v5 전환 이유를 "탱커 중심 메타 해체 + 매치 하한선(floor) 올리기"라고 설명 — TTK보다 역할 수로 교전 템포를 조정한 사례 [21].
- **Hitscan vs Projectile**: Hitscan은 레이캐스트 즉시 판정(배우기 쉬움, 랙 보상 필수), Projectile은 탄속·낙차(리드샷, 서버 부하↑). Apex Legends는 전 무기 투사체이며 에너지탄은 드래그만 다름 (Respawn 무기 디자이너 Sean Slayback, 2차 보도) [22]. Roblox 공식 Weapons Kit은 투사체 기반이며 "탄속을 매우 높이면 레이캐스트처럼 보인다"고 문서에 명시 [23].
- **서버 권위 + 랙 보상**: 클라이언트는 입력만 보내고 서버가 상태 결정(치트 방지) → 클라이언트 예측·서버 리컨실리에이션·엔티티 보간·랙 보상(서버가 시간을 되감아 판정) 순서로 쌓는다 (Gambetta 시리즈, Valve Bernier 논문) [24][25]. VALORANT는 128틱(프레임당 7.8125ms, 코어당 3게임 목표로 실제 예산 ~2.34ms)을 "수비자가 반응할 시간" 확보용으로 채택, 서버 프레임을 50ms→2ms 미만으로 최적화 (Riot 공식 2020-08-31) [26]. Overwatch는 ECS + 결정론적 시뮬레이션, 커맨드 프레임 16ms(토너먼트 7ms) — 예측 틀리면 서버 스냅샷으로 롤백 후 입력 재생 (GDC 2017 Tim Ford; ms 수치는 Edgegap 요약 2차) [27][28]. CS2는 틱 올리는 대신 "서브틱"으로 입력 시각을 틱 사이에서 기록 (Valve 발표, 2차 보도; 공식 64틱) [29].
- **맵 흐름 (3-lane 등)**: Treyarch BO7: "양쪽 플랭크 2개 + 중앙 1개가 두 스폰을 잇는다", 디자인 디렉터 Matt Scronce "모든 레인에는 목적이 있어야 한다", "엄폐물 없으면 그냥 열린 공간" (Xbox Wire 2025-10-27 공식) [10]. CS/VALORANT류는 2~3 사이트 + 미드 구조로 정보전(스모크·유틸)이 레인 선택을 대체.
- **무기 역할 분담**: VALORANT 공식 아스널은 20종(사이드암 6·SMG 2·샷건 2·라이플 4·스나이퍼 3·헤비 2·근접 1) — 가격대별로 "에코/포스/풀바이" 라운드 경제와 결합 [30]. Roblox Weapons Kit은 9종(피스톨·샷건·AR·SMG·스나이퍼·석궁·유탄·로켓·레일건)으로 소규모 프로젝트의 최소 역할 세트 참고 [23].
- **매치메이킹/랭크**: VALORANT 공식 개발 노트: 파티는 2랭크(6티어) 이내, 14일 미플레이 시 랭크 숨김 [31]. CS2는 MR12(정규 24라운드, 13선취)로 매치 시간을 줄여 "더 자주 플레이"를 노림 (Valve 공지 인용 2차) [32]. 랭크 티어 수·RR 수치는 3rd-party 자료만 있어 미검증.
- **배틀패스**: 시즌 단위 보상 트랙이 리텐션 엔진. Fortnite는 패스 완주 시 V-Bucks 환급으로 "다음 패스 무료" 루프를 만들고 Fortnite Crew(월 구독)가 패스+V-Bucks를 묶음 — 가격(950~1,000 V-Bucks, $11.99/월)은 3rd-party 가이드 기준이라 미검증 [33].

## 6. 함정 (흔한 실패)

- **클라이언트를 믿는 히트 판정**: 클라이언트가 "맞았다"를 보내게 하면 에임봇·데미지 핵이 즉시 생긴다. 서버 권위 + 랙 보상이 기본값이어야 하며, 나중에 바꾸면 전체 무기 코드를 다시 쓰게 된다 [24][25].
- **TTK를 정하지 않고 무기부터 만들기**: TTK는 맵 거리·엄폐 밀도·힐 유무와 묶여 있다. 무기별 수치를 먼저 쌓으면 밸런스가 아니라 "누가 먼저 봤나" 게임이 되거나 반대로 스펀지 느낌이 난다. CoD도 시리즈마다 TTK 목표를 먼저 공개한다 [20].
- **틱레이트/서버 비용 과소평가**: VALORANT는 128틱 때문에 프레임당 2ms대 예산을 맞추려 서버 코드·OS·CPU까지 튜닝했다. 소규모 팀이 고틱 서버를 약속하면 운영비로 죽는다 — 서브틱(CS2)이나 보간 지연 같은 설계적 대안을 먼저 본다 [26][29].
- **레인 없는 맵**: 플레이어가 "어디로 가야 하는지" 못 배우면 스폰킬·캠핑·교전 공백이 생긴다. Treyarch의 "모든 레인에 목적" 원칙처럼 각 경로의 위험/보상을 의도적으로 설계해야 한다 [10].
- **투사체 무기를 랙 보상 없이 도입**: 투사체는 hitscan보다 네트워크 동기화가 어렵고(발사 시점·탄속·보간), 리드샷이 랙에 따라 달라지면 "총이 이상하다"는 평이 나온다. Apex처럼 전부 투사체로 가려면 넷코드 투자가 전제다 [22].
- **매치 길이·인원 미스매치**: 100명 BR은 동접이 모자라면 매치가 안 돌아간다. Free Fire(50명·~10분)·Roblox 아레나(16~32명)처럼 플랫폼의 세션 길이와 동접 규모에 맞춘 인원이 먼저다 [16][17].
- **배틀패스를 처음부터 넣고 콘텐츠 공급을 못 맞춤**: 시즌 트랙은 매 시즌 새 보상이 필요하다. 파이프라인 없이 넣으면 2시즌째에 빈 패스가 되고 리텐션 엔진이 역효과를 낸다 (Fortnite류 모델 [33]).
- **공식 수치 없이 시장 판단**: 슈터 플레이어 수는 트래커마다 2배 이상 차이 난다(VALORANT 1,400만 vs 3,300만). Steam 공식 차트·실적 공시(Krafton·Sea)만 1차 자료로 쓰고 나머지는 미검증 표기 [1][11][13].
